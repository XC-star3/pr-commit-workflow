# Commit message format

Use a repository-supported Conventional Commit style when one exists:

```text
<type>(<scope>): <imperative summary>

What: ...
Why: ...
How: ...

Tests: ...
Review: human-approved | ai-reviewed
Risks: ...
```

The subject describes the change. What describes the result, Why describes the need, and How describes the implementation. Keep each field specific enough that a maintainer can understand the change without reading the entire diff. Do not claim a test, review, issue link, or user intent that did not occur.
